Renku remote cluster components have been installed in the namespace "{{ .Release.Namespace }}".
Renku sessions from the main deployment will run in this namespace.

{{- if .Values.crossClusterAccess.enabled }}
{{- $saName := include "renku-remote.crossClusterServiceAccountName" . }}

1. Build the kubeconfig the main Renku deployment uses to reach this cluster:

  NS={{ .Release.Namespace }}
  SECRET={{ $saName }}-token
  SERVER=<public URL of this cluster's Kubernetes API, e.g. https://k8s.example.org:6443>
  CA=$(kubectl -n $NS get secret $SECRET -o jsonpath='{.data.ca\.crt}')
  TOKEN=$(kubectl -n $NS get secret $SECRET -o jsonpath='{.data.token}' | base64 -d)
  cat > remote-cluster.yaml <<EOF
  apiVersion: v1
  kind: Config
  clusters:
    - name: remote
      cluster:
        certificate-authority-data: $CA
        server: $SERVER
  contexts:
    - name: remote
      context:
        cluster: remote
        namespace: $NS
        user: remote
  users:
    - name: remote
      user:
        token: $TOKEN
  current-context: remote
  EOF
  KUBECONFIG=remote-cluster.yaml kubectl get amaltheasessions

2. Add the kubeconfig to the secret referenced by
   `dataService.remoteClustersKubeconfigSecretName` in the main Renku deployment,
   then register the cluster through the Renku `/clusters` API.
   You will have to restart the data services, k8s watcher and secret service so
   that they pick up the new cluster.
{{- end }}

{{- if .Values.sshProxy.enabled }}
{{- $fullname := include "renku-remote.fullname" . }}

SSH proxy enabled. To register this cluster with the main Renku deployment:

1. Read the public part of this cluster's host key (hostkey-R) and its fingerprint:

  NS={{ .Release.Namespace }}
  kubectl -n $NS get secret {{ $fullname }}-ssh-proxy -o jsonpath='{.data.openSshHostKey}' \
    | base64 -d | ssh-keygen -y -f /dev/stdin | tee /tmp/hostkey-R.pub

2. Register this cluster at the main Renku deployment (`POST /api/data/clusters`), amending the
   payload with an `ssh` section, e.g.:

  {
    "name": "<cluster name>",
    "...": "existing fields",
    "ssh": {
      "host": "<public IP/hostname of the ssh-proxy Service>",
      "port": {{ .Values.sshProxy.port }},
      "username": "renku-proxy",
      "host_public_key": "<public key from step 1>",
      "session_secret_name": "{{ .Values.sshProxy.sessionKeysSecretName }}"
    }
  }

   The response contains `ssh.auth_public_key` (authkey-R).

3. Configure this proxy with that key and upgrade this release:

  helm upgrade {{ .Release.Name }} helm-chart/renku-remote \
    --namespace $NS \
    --reuse-values \
    --set sshProxy.authorizedKey="<auth_public_key from step 2>"

   Until this step, the proxy rejects all connections from the main cluster.
{{- end }}
